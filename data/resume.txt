NoteBookLLM · Python, JavaScript, LLM APIs
GitHub: github.com/pranay-reddy2/NoteBookLLM
Backend GitHub: github.com/pranay-reddy2/NoteBookLLM_Backend
NoteBookLLM is Pranay's flagship AI project. It is a full-stack RAG-powered note-taking tool that lets users upload documents and query them with natural language instead of manually searching.
Tech stack: Python backend, JavaScript frontend, LLM APIs, vector database for embeddings.
Purpose: Enable context-aware question answering over personal documents using Retrieval-Augmented Generation.
Design tradeoffs: Chose RAG over fine-tuning because RAG works with any document without retraining the model. Kept frontend and backend in separate repos for clean separation of concerns.
What Pranay would do differently: Add user authentication and multi-user support from day one instead of building it as a single-user tool first. Would also implement chunk reranking to improve retrieval quality.
Actively maintained — updated within the last month with ongoing feature development.

GYM_CRM · React, Node.js, Express.js, PostgreSQL
GitHub: github.com/pranay-reddy2/GYM_CRM
GYM_CRM is a production-level full-stack gym management CRM built with commercial intent.
Tech stack: React, Vite, Tailwind CSS, TanStack Query on frontend; Node.js, Express.js on backend; PostgreSQL (Neon) for database; Vercel for frontend deployment.
Purpose: A one-time purchase alternative to subscription-based gym software targeting small gym owners.
Features: Member management, check-ins, payments, trainer assignments, Kanban lead pipeline, churn risk alerts, AI-powered message composer.
Design tradeoffs: Chose PostgreSQL over MongoDB for relational integrity between members, payments, and check-ins. Used name-based joins in checkins table which is technical debt.
What Pranay would do differently: Replace name-based joins with proper foreign keys from day one. Add proper auth instead of relying on deployment-level security.
